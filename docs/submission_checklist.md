# Project Submission Checklist

## Technical

- [ ] The project README states the problem, variables, objective, constraints, and assumptions.
- [ ] The code or notebook runs from a clean environment.
- [ ] Random seeds and important numerical settings are recorded.
- [ ] Figures have readable labels, units, legends, and captions.
- [ ] Reported results can be traced to committed code.
- [ ] Large datasets and model checkpoints are excluded or linked appropriately.

## Report

- [ ] The final PDF is saved as `report/report.pdf`.
- [ ] The PDF opens correctly in GitHub's viewer.
- [ ] Equations, tables, and figures are legible.
- [ ] References and external resources are cited.
- [ ] The report contains only original work and permitted assistance.

## URL and repository

- [ ] The project link works in a signed-out browser.
- [ ] The report link points to the intended PDF.
- [ ] The latest changes are pushed to `main`.
- [ ] No credentials, private data, exam content, or instructor-owned files are committed.
- [ ] If an immutable submission is needed, use the file URL from the final commit rather than the moving `main` URL.
